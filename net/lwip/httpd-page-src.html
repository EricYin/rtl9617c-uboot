更新 U-Boot

写入 boot 分区的双 FIP 副本（先写并校验 FIP1，再写 FIP0）。镜像必须保留本机的 GPT / BL2 / BL31。

FIP 引导镜像

镜像为完整的 boot 区引导镜像（含 GPT / BL2 / BL31 与双 FIP），写入时先校验并写 FIP1，再写 FIP0。

警告
  • 更新 U-Boot 属高危操作，可能损坏设备
  • 请务必选择与本机匹配的引导镜像
  • 更新期间请勿断电

重建 UBI

重建 UBI 时板级数据卷（ubi_Config、ubi_fpga 等）原位保留、数据不动，fip 与 rootfs_data 按 64 MB / 174 MB 重建；安装固件前必须先导入 ubi_Config 镜像。勾选“删除所有分区”会连 ubi_Config 一起删除，需要二次确认。若 UBI 已损坏无法识别，将改为整区擦除，此时数据卷无法保留。

警告
  • 数据卷（ubi_Config/ubi_fpga）原位保留，系统卷将被清空
  • 若 UBI 无法识别将整区擦除，建议先在「分区备份」导出重要卷

分区备份

导出 UBI 卷或 MTD 分区内容。备份 fip 卷即可导出当前整套固件。

说明
  • MTD 备份为物理主数据，坏块填充 FF，不包含 OOB
  • 整片备份可用于「闪存管理」的整片恢复

数据卷

ubi_Config（工厂校准与身份数据）与 ubi_fpga（FPGA 固件）等板级卷。重建 UBI 时这些卷原位保留；若卷不存在，在此导入镜像时自动创建。

闪存管理

向任意分区写入镜像、从整片备份恢复，或清除坏块标记。

写入分区

向任意 UBI 卷或 MTD 分区写入镜像，写入前无内容校验，请确认目标；MTD 分区写入要求镜像大小按擦除块（128 KiB）对齐。

整片恢复

从偏移 0 恢复完整主数据（含引导与板级数据），分段写入并校验。文件大小必须与 Flash 容量一致。

清除坏块标记

擦除整片 NAND（包括出厂坏块标记），所有数据将丢失。

警告
  • 写入与恢复操作直接修改 Flash 内容，请反复确认目标
  • 整片恢复文件必须来自本机的完整备份

环境变量

恢复网络使用 httpd_ipaddr / httpd_netmask（下次进入生效）；httpd_dhcp 设为 0 关闭 DHCP、设为 1 启用。

恢复服务与网络

保存后立即写入 Flash，下次进入恢复模式生效；ipaddr / netmask 保存时自动映射为 httpd_ipaddr / httpd_netmask，值留空表示删除该变量。

其他变量

说明
  • bootcmd 由引导程序在每次开机时重设，在此修改无效
  • 关闭 DHCP（httpd_dhcp=0）后需设置 httpd_ipaddr 才能访问本页面

网页终端

此终端可执行任意 U-Boot 命令，请勿暴露在不可信网络中。

启动与重启

从 fip 卷启动系统、从内存试跑镜像，或重启设备。

启动系统

从 UBI 的 fip 卷读取固件并启动 OpenWrt。

内存启动

上传 FIT 镜像直接从内存启动，不写入 Flash。

重启设备

重启后按住 reset 键可再次进入恢复模式。

说明
  • 内存启动适合验证新固件，不改动 Flash
  • 启动系统后本页面将不可用
